# 内容以 TS 模块实现，而非 JSON + 效果 DSL

概要设计 §14.1 要求技能、宝物、敌人全部用 JSON / ScriptableObject 配置，效果用 DSL 或效果组件拼装。但 noname 引擎的技能本身就是 `async content` 函数，"按原版描述执行"的技能本质是任意 JS 逻辑（例如【离间】的 `filter` 依赖角色数量与性别，无法组件化），用自研 DSL 重写等于重造一套引擎。决定：**含逻辑的内容（技能、敌人行为、宝物效果、融合/进化配方）用 TS 模块实现**，直接复用 `noname` 公开导出与标包实现；**纯数据（地图骨架、事件文本、价格、词缀参数、掉落权重）用配置文件**。

## 后果

- 内容评审需要读代码，不能只看 JSON；技能元数据（标签、品质、等级数值）单独成表，供掉落与配方系统消费。
- 批量数值调整只覆盖真正数据化的部分；技能逻辑的平衡仍靠改 TS。
